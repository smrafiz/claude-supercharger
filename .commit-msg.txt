fix(guards): 2.24.10 — 2.24.9's harness-tamper fix was incomplete; the FP survived it

2.24.9 stripped scope-FILE references before the target test, which fixed writing
a sentinel in isolation. It did not fix the reported case: the install-dir arm
still matched ANY path beneath the install dir, including the audit LOGS. Because
the verb and target tests match independently — and on different LINES of a
compound command — reading an audit log in the same command as any touch/rm was
still denied. 2.24.9's tests passed only because they used single-purpose commands.

Fixed at the target instead, which let the stripping pass be deleted rather than
leaving two overlapping mechanisms:
- code dirs (hooks/, lib/, tools/) match per-file
- the install dir and the data dirs (scope/, audit/) match only as whole DIRECTORIES
- the kill-switch keeps its own arm

Still denied: removing the install dir, the scope dir or the audit dir; removing a
tools/ script; overwriting lib/utils.sh or a hook; creating the kill-switch.
Now allowed: reading an audit log, writing or clearing a scope sentinel.

Verified against the DEPLOYED hook with fully literal paths in one compound
command: audit read (69 lines), sentinel create, sentinel remove all succeed.

Method note: the earlier verification used a string-concatenation trick to route
around the guard while working, and that habit hid the bug — the concatenated path
never matched the target, so the FP looked fixed. Guard fixes must be exercised
with the literal input a user would type.
